# 소스 발굴 & 콘텐츠 생성 가이드 (표준)

> `/sources` 페이지의 운영 방법론. 이 문서만 읽으면 이전 대화 기록이 없는 Claude도 동일한 방식으로 소스 발굴을 이어갈 수 있어야 한다.

## 이 페이지가 왜 존재하는가

여러 SNS 계정(쓰레드, 유튜브 쇼츠, 틱톡, 인스타그램)의 트래픽을 키우려면 매일 소재가 필요하다. 그런데 **소재를 찾는 방식과 "잘 먹히는 형태"는 플랫폼마다 완전히 다르다.** 이 페이지는 그 차이를 구조화해서, 소재를 한 번 찾으면 여러 플랫폼용으로 나눠 쓸 수 있게(원소스 멀티유즈) 관리하는 도구다.

## 핵심 원칙: 플랫폼마다 통하는 방식이 다르다

과거 시행착오에서 확인된 사실:
- **잡학/트리비아(TIL형) 콘텐츠는 유튜브 쇼츠·틱톡·인스타에는 잘 먹히지만, 쓰레드에서는 검증된 바이럴 사례가 없었다.**
- 쓰레드 알고리즘은 좋아요보다 "댓글의 길이"를 강한 신호로 본다. 즉 **정보를 던지는 곳이 아니라 공감/논쟁이 댓글로 이어지는 곳**이다.
- 그래서 같은 사실이라도 쓰레드용은 "나의 경험/반응"으로 포장하거나 "사람마다 답이 갈리는 질문형"으로 바꿔야 하고, 유튜브/틱톡용은 순수 정보 전달(훅-반전-마무리)로 가도 된다.

**결론: 소재를 찾을 때부터 "이 소재가 어느 플랫폼에 맞는가"를 먼저 판단하고 분류해야 한다.** 하나의 소재를 억지로 모든 플랫폼에 우겨넣지 않는다.

## 콘텐츠 유형 태그 (8종)

| 태그 | 설명 | 예시 |
|---|---|---|
| `TRIVIA` | 반전/신기한 사실형 | "코끼리가 실을 못 끊는 이유" |
| `LIFEHACK` | 실용 정보/팁 | 청소 꿀팁, 요리 팁 |
| `EMOTIONAL` | 감동/뭉클 | 반려동물 감동 서사 |
| `HUMOR` | 웃김/드립 | 강아지 밥그릇 시위 영상 |
| `MOTIVATION` | 자극/동기부여 | 극복 서사, 팩폭형 조언 |
| `RANKING` | 랭킹/리스트형 | "TOP5", "~가지" 나열형 |
| `PERSONAL_STORY` | 1인칭 경험담 | "회사에서 억울했던 일" |
| `DEBATE` | 호불호/논쟁 유발 | "이거 나만 이상함?" |

## 채널 발굴 방법

**도구**: `유투브파인더` MCP 커넥터 (`search_shorts`, `discover_channels`, `get_trending`)

1. `search_shorts`로 관심 있는 키워드를 조회한다. 예: "신기한 사실", "미스터리 소름", "생활 꿀팁"
   - `minViews`를 처음엔 낮게(2~3만) 잡고, 결과가 너무 적으면 더 낮춘다
   - `uploadWithinDays`는 60~180일 정도로 넉넉하게
2. 반응이 좋은 채널이 하나 발견되면, 그 **채널명으로 재검색**해서 히스토리를 통째로 훑는다 (예: `search_shorts(query: "문명쇼크", minViews: 10000, uploadWithinDays: 180)`). 여러 편을 한 번에 보면 그 채널의 "훅 공식"이 패턴으로 보인다.
3. `discover_channels(category, videoType)`로 카테고리별 급상승 채널도 주기적으로 훑는다. 카테고리: 건강/의학, 영화/드라마 리뷰, 연예인/이슈, 재테크/부동산, 동기부여/명언, AI/IT 꿀팁, 라이프스타일/Vlog, 반려동물, 블랙박스/사건사고, 뷰티, 요리, 여행, 전체
4. 구독자 20만 이하 채널 위주로 본다 (이 도구 자체가 그렇게 필터링되어 있음 — 대형 채널보다 "지금 뜨는" 채널을 잡기 위함)

**쓰레드용 소재는 다른 방식으로 찾아야 한다** (위 원칙 참고): 유튜브 쇼츠 채널을 아무리 뒤져도 쓰레드에 맞는 소재는 잘 안 나온다. 쓰레드는 실제 쓰레드 벤치마크 계정(`ut_benchmark_items`)이나 온라인 커뮤니티의 "나만 그런가" 류 공감 글에서 찾는 게 맞다.

## 유튜브 영상 자막(스크립트) 가져오기

채널의 "훅 공식"을 제목·썸네일만 보고 추측하지 말고, 실제 자막을 읽어야 정확하다. 유튜브 페이지를 브라우저로 열어서 클릭으로 긁는 방식은 불안정하다(타이밍 이슈, 자막 패널 렌더링 지연). **Node.js로 직접 유튜브 API를 호출하는 것도 최근 안티스크래핑 강화로 막혀 있다**(`timedtext` URL이 서명돼있고 세션 종속적이라 빈 응답만 옴, 2026-08-24 직접 확인).

**유일하게 확인된 안정적인 방법**: Python `youtube-transcript-api` 라이브러리.

```bash
pip install youtube-transcript-api
```

```python
from youtube_transcript_api import YouTubeTranscriptApi

api = YouTubeTranscriptApi()
transcript = api.fetch("영상ID", languages=["ko"])  # 영상ID는 watch?v= 뒤의 값
full_text = " ".join(seg.text for seg in transcript)
```

2026-08-24 실제 영상(4EoV0aDqj_0, 19분)으로 검증함 — 496개 구간, 사용자가 직접 유튜브에서 복사한 자막과 글자 그대로 100% 일치. `languages=["ko"]`가 없으면 기본 언어로 가져오니, 한국어 영상은 꼭 지정할 것.

## 저작권 안전 수칙 (중요)

- 채널/영상에서 가져오는 것은 **사실관계(fact)뿐**이다. 원본 영상의 스크립트, 나레이션 문장, 자막을 그대로 옮기지 않는다.
- 소재 등록 시 `raw_notes`에는 "이 영상이 다루는 핵심 사실"만 한두 문장으로 요약해서 적는다. 대본을 그대로 붙여넣지 않는다.
- 실제 콘텐츠 생성 시(3번 탭) 시스템 프롬프트에 "원본 문장을 그대로 옮기지 말고 완전히 새로 써라"는 지침이 이미 들어가 있다(`app/api/generate-content/route.ts` 참고).

## URL로 가져오기 (자동 수집)

2번 탭 상단의 "🔗 링크로 가져오기"에 URL을 한 줄에 하나씩 붙여넣으면 자동으로 처리된다:

1. **중복 체크**: `hub_source_items.source_url`에 이미 있으면 건너뛴다 (같은 링크 두 번 등록 안 됨)
2. **메타데이터 추출**: 페이지의 `og:title`, `og:description`, `og:site_name` 태그를 서버에서 읽어온다 (공유 미리보기용으로 각 플랫폼이 공개하는 정보라 안전함)
3. **채널 자동 매칭/생성**: `og:site_name` 기준으로 기존 채널과 느슨하게 매칭하고, 없으면 새 채널을 "후보" 상태로 자동 생성
4. **AI 자동 분류**: 선택한 AI(Claude/Gemini)가 제목+설명을 보고 `content_type`, `platform_fit`, `raw_notes`(사실관계 요약, 원문 그대로 옮기지 않음)를 자동으로 채워서 등록

이 방식은 유튜브뿐 아니라 **쓰레드/틱톡/인스타 링크도 그대로 처리**할 수 있다 — 사용자가 평소 SNS 둘러보다 발견한 링크를 그때그때 모아서 붙여넣기만 하면 되는 구조. 각 플랫폼 전용 자동 검색(크롤링)은 이용약관상 리스크가 있어서 아직 구현하지 않았고, 이 "링크 투입 → 자동 분석" 방식이 현재 채택된 대안이다.

**주의**: og 태그가 부실한 페이지(로그인 필요, JS 렌더링 의존 등)는 제목/설명이 비거나 부정확할 수 있다. 이 경우 결과를 확인하고 2번 탭에서 수동으로 수정한다.



### 방법 A: 페이지에서 직접 등록 (소량일 때)
`/sources` → 1번 탭에서 "+ 채널 추가" → 2번 탭에서 "+ 소재 추가"

### 방법 B: SQL 일괄 등록 (여러 건일 때)
한 번에 여러 채널/소재를 넣을 땐 Supabase SQL Editor에서 INSERT문을 직접 실행하는 게 빠르다. 예시 패턴:

```sql
insert into hub_source_channels (name, platform, url, subscriber_count, content_types, platform_fit, notes, status)
values (
  '채널명', 'youtube', 'https://...', '5.2만',
  array['TRIVIA'], array['youtube_shorts','tiktok'],
  '이 채널의 특징 메모', '추적중'
);

insert into hub_source_items (channel_id, title, source_url, views, content_type, platform_fit, raw_notes, status)
values (
  (select id from hub_source_channels where name = '채널명' limit 1),
  '영상 제목', 'https://youtube.com/watch?v=...', '174.0만',
  'TRIVIA', array['youtube_shorts','tiktok','instagram'],
  '핵심 사실관계 요약 (원본 문장 그대로 X)', '미가공'
);
```

(현재 MCP 도구 중 이 두 테이블에 직접 insert하는 전용 툴은 없다. `홍허브:run_sql`은 SELECT 전용이라 이 작업엔 못 쓴다. Supabase SQL Editor에 직접 붙여넣어 실행할 것.)

## 콘텐츠 생성 워크플로우 (3번 탭)

1. 소재 선택 (또는 주제 직접 입력)
2. 페르소나 선택 (유쓰레드의 `ut_personas`/`ut_system_personas`를 그대로 불러옴 — 새 페르소나는 유쓰레드 쪽에서 추가하면 여기 자동 반영됨)
3. 타겟 플랫폼 선택 (쓰레드/유튜브쇼츠/틱톡/인스타) — 플랫폼별 포맷 규칙이 자동으로 강제됨
4. AI 엔진 선택 (Claude / Gemini) — 둘 다 `app_config` 테이블의 키를 그대로 씀, 별도 설정 불필요
5. "✨ 콘텐츠 생성" → 결과 확인 → 마음에 안 들면 다시 생성 (다른 AI로 바꿔서 비교도 가능)

## 소재 상태 관리

`미가공` → `가공완료` → `발행완료` 3단계로 관리한다. 실제로 콘텐츠를 만들어서 발행했으면 상태를 갱신해서, 나중에 같은 소재를 중복으로 안 쓰게 한다.

## 다음에 이어서 할 작업 체크리스트

새 세션에서 이 페이지 작업을 이어받았다면:
1. `/sources` 1번 탭에서 이미 등록된 채널 목록 확인 (중복 등록 방지)
2. 2번 탭에서 `미가공` 상태 소재가 남아있는지 확인 — 있으면 그것부터 소진
3. 없으면 위 "채널 발굴 방법"대로 유투브파인더로 새로 탐색
4. 새 소재는 반드시 `content_type` + `platform_fit` 태그를 붙여서 등록 (안 붙이면 3번 탭에서 필터링이 무의미해짐)
5. 쓰레드용 소재가 유독 부족하기 쉬우니, 유튜브 채널만 뒤지지 말고 쓰레드 자체 벤치마크(`ut_benchmark_items`)도 주기적으로 확인
